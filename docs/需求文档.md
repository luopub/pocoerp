# PocoERP 需求文档（v1.17）

> 面向小规模跨境电商卖家、以产品管理为核心的轻量级 ERP 系统。
> 状态：**需求定稿，待开工确认** —— 用户明确确认后开始开发。

---

## 1. 项目背景与目标

小规模跨境电商卖家，核心诉求是管理**产品成品库存**，并覆盖两条供给链路：

1. **直接采购成品**：从供应商购买成品 → 入库。
2. **委外加工**：自购原材料 → 多道供应商工序加工 → 成品入库。

发货去向为电商平台或直发客户，第一期**手动出库**。

系统目标：清晰掌握"有多少货、货怎么来的、成本多少、发到哪去了"。

---

## 2. 已确认的关键决策

| 项目 | 决策 |
|------|------|
| 产品结构 | **SPU + SKU 两级结构**（v1.5 起）：产品/原材料下挂 1~n 个 SKU 变体（颜色/尺寸/长短等）；库存、成本、出入库均按 SKU 跟踪 |
| 物料清单 | 简化版 BOM：1 种**主材** + 0~n 种**辅料**（各记单位用量，可按 SKU 分别设置；辅料指定投入工序），不做多层 BOM |
| 出库方式 | 第一期只做**手动出库**，预留平台对接扩展 |
| 出库渠道 | 出库时记录**去向渠道**（渠道可自定义维护），支持按渠道统计 |
| 成本核算 | 需要：记录采购价、加工费，按**移动加权平均**核算成品单位成本 |
| 工序流转 | 简单记录：加工单记录每道工序的供应商、开始时间、投入/产出数量；半成品不建档 |
| 共享主材加工单 | 同一主材可跨产品/SKU 共享：加工单支持**多产品合并下达**（要求同主材、同工序模板），计划按 SKU 分列、定向工序（如裁片）完成前可调整分配比例，逐工序跟踪**在制可产数量**（v1.15 新增） |
| 仓库 | **单仓**，发货即出库，不跟踪在途 |
| 用户权限 | 登录体系 + **多角色权限** |
| 技术栈 | **Node.js**，云服务器部署，网页版 |
| 附加功能 | 导出 Excel、产品图片、库存预警（不需要多币种） |
| 业务规模 | 中等：SKU 100~500，每月单据几百张 |
| 耗材处理 | 耗材（包装袋/标签等）不建库存、无单据；**按 SKU** 设"单位耗材成本"估算值，入库核算时计入产品成本（v1.4 新增，v1.16 起由产品级改为 SKU 级） |
| 虚拟组合产品 | 支持任意产品任意数量的捆绑装：不入库、无实物库存，可售数量由组件派生，出库展开扣减组件库存（v1.6 新增） |
| 平台产品映射 | 每 SKU 可挂多条映射（平台+账号+两个自由格式 ID），单值可重复、组合唯一；**销售出库的唯一入口**（不能直接出库基础产品）；默认映射=非平台产品/默认账号（v1.10 强化） |
| 采购与付款 | 采购单支持分次入库与差异结案；采购单/加工单记录付款（未付/部分/已清），供应商对账含欠款天数（v1.13 新增） |
| 数据库 | **MongoDB** |
| 角色方案 | 管理员 / 仓管 / 只读 三种 |

| 角色 | 权限 |
|------|------|

## 4. 功能模块详细需求

### 4.1 登录与用户管理
- 用户名 + 密码登录，会话保持（Token / Cookie）。
- 管理员可创建、停用、重置密码、分配角色。

### 4.2 产品（成品）管理
- 产品采用 **SPU + SKU 两级结构**：一个产品（SPU）下挂 1~n 个 SKU（变体），
  变体由规格属性区分（如颜色、尺寸）；无变体的产品只建 1 个默认 SKU。
- **产品类型**分两种：
  - **实物产品**：正常采购/加工/入库/出库；
  - **虚拟组合产品**（v1.6 起）：不采料、不加工、**永不入库、不持有实物库存**；
    每个 SKU 配置**组成明细**（组件产品 SKU + 数量，**任意产品、任意数量组合**，
    如"带内衬袋的豆袋椅套"= 某椅套 SKU × 1 + 某内衬袋 SKU × 1）；
    其可售库存为派生值 = min( ⌊各组件库存 ÷ 单位用量⌋ )，仅用于展示与出库校验。
- **产品（SPU）字段**：编号 PRD（唯一）、名称、分类、来源方式（直接采购/委外加工/两者皆可）、
  **默认供应商**（同一产品的各 SKU 通常来自同一供应商；不同批次采购时可改）、备注、状态。
- **SKU 字段**：子编号（SPU 编号-序号，如 PRD000001-001）、规格属性（如 颜色=红、尺寸=大）、
  图片（实物与虚拟组合产品的 SKU 均支持上传）、安全库存阈值、
  **单位耗材成本**（估算值，默认 0；耗材不建库存，仅计入成本，见情景 4；v1.16 起由 SPU 级改为 SKU 级）、
  **预警参数**（历史窗口天数、可用天数门槛，可空=继承 SPU/全局默认）、备注、状态（启用/停用）。
- 委外加工类产品需配置**物料清单**（简化版 BOM）：
  - **主材** 1 种：原材料（精确到材料 SKU）+ 单位用量，在**首道工序**发料；
  - **辅料** 0~n 种：原材料 SKU + 单位用量 + **投入工序**（如拉链在"缝制"工序投入）；
  - 单位用量可**按产品 SKU 分别设置**（如大号椅套用布 1.5 m、小号 1.0 m），未单独设置的 SKU 用默认用量。
- 列表支持搜索、筛选、导出 Excel；库存预警**按 SKU** 判断（低于安全库存时醒目标记）。
- **SKU 建档规则**（v1.16 起）：新建产品自动生成 1 个默认 SKU（无规格属性）；
  继续新增 SKU 前，须先为无规格属性的 SKU 补全规格属性（否则多个无属性 SKU 无法区分）。
- **删除**（v1.16 起）：管理员可删除产品或 SKU，但被使用的不可删——
  有库存、有库存流水、被采购/加工/出库/退货/盘点单引用、或被虚拟组合产品引用时禁止删除；
  产品至少保留 1 个 SKU；删除时同步清理其平台映射。

### 4.3 原材料管理
- 原材料同样采用 **SPU + SKU 两级结构**（如拉链按长短分 SKU、布料按颜色分 SKU）；
  无变体则只有默认 SKU。
- 字段：编号 MAT（唯一）、名称、单位、默认供应商、备注、状态；
  SKU 子编号（如 MAT000001-001）、规格属性、安全库存阈值。
- 原材料库存实时数量 + 移动加权平均成本，**按材料 SKU 跟踪**。
- 库存预警按 SKU 判断。

### 4.4 供应商管理
- 字段：名称（唯一）、类型（成品供应商 / 原材料供应商 / 加工商，可多选）、联系人、电话、备注。

### 4.5 采购管理

#### 4.5.1 成品采购单
- 单头：单号（自动生成）、供应商、采购日期、备注。
- 明细：**产品 SKU**、数量、单价、**已入库数量**。
- **分次入库**（v1.13 起，见情景 13）：
  - 状态流转：**待入库 → 部分入库 → 已入库**（可作废）；
  - 每次到货录入本次入库数量（≤ 剩余数量），逐次累加；
  - 供应商少发/不再发货时，可将未交数量**结案为差异**（记录差异原因），单据转已入库；
- 确认入库时：成品库存（按 SKU）增加，按移动加权平均更新成本；入库单位成本 = 采购单价 + 该 SKU 的**单位耗材成本**（见 4.2，下同）。
- **批次灵活性**：同一产品不同批次可用不同供应商、不同价格（供应商在单头、价格在明细，逐单记录）；下单时默认带出产品默认供应商和最近采购价，可修改。
- **付款记录**（v1.13 起，见情景 17）：应付金额（明细合计）+ 付款记录数组（日期、金额）；
  付款状态自动计算：未付款 / 部分付款 / 已付清。

#### 4.5.2 原材料采购单
- 结构同上（明细为**材料 SKU**，含分次入库与付款记录），入库时增加原材料库存并更新加权成本。

### 4.6 委外加工管理（加工单）
- 单头：单号、**产品组**（1~n 个产品 SPU；多产品合并下达时，要求各产品**共用同一主材 SKU
  且工序模板一致**，否则分别建单）、创建时间、状态。
- **主材输入**（v1.17 起）：建单时必须指定**主材 SKU 及输入量**，作为首道工序的输入；
  首道工序开始时系统按该输入自动发料（扣减原材料库存，库存不足则工序不能开始）。
- **计划明细**：按 **SKU 分列计划数量**（如豆袋椅套：大号 100 件、小号 50 件），
  多产品工单可跨产品混排；**定向工序（通常为裁片）完成前，各 SKU 计划比例可调整**
  （总量受已发主材量约束），适应"同一批布料裁片时才确定各产品/尺寸各裁多少"的
  分配方式（v1.15 起，见情景 19）。
  **用料约束**（v1.17 起）：Σ（各 SKU 计划数量 × 该 SKU 单位用量）**≤ 主材输入量**，
  建单时实时校验，超出不得提交。
- **按工序发料**：
  - 每道工序开始时可记录发料：材料 SKU、数量、发料时间；确认后原材料库存扣减。
    **首道工序的主材发料由建单时的"主材输入"自动生成**（v1.17 起），仍可按需补发。
  - 按物料清单自动计算应发数量（Σ 各 SKU 计划数量 × 对应 SKU 单位用量；多产品工单
    按各产品 BOM 汇总），可手工调整。
  - 主材通常在首道工序发料；辅料在其配置的工序发料（如拉链在缝制工序发出）。
  - 支持一道工序发多种料、同一材料分多次发。
- **工序记录**（按产品工序模板生成，顺序执行）：
  - 每道工序记录：加工供应商、**开始时间**、完成时间、加工费（单价 × 数量 或 总额）、备注。
  - 投入/产出数量**按 SKU 分别记录**（如裁片工序提交：大号 100、小号 50；缝制工序同样分别记录大号/小号数量）；
    **定向工序之前的共用料工序（如印花）可按材料总量记一笔**（如印花产出 490 米），不分 SKU（v1.15 起）。
  - 当前工序标记"完成"后解锁下一道工序。
- **在制可产数量**（v1.15 起，见情景 19）：每道工序完成后，工单显示剩余在制材料折算的
  **各 SKU 可产数量**（= 剩余在制材料量 ÷ 该 SKU 单位用量，逐 SKU 列出，如
  "余布 490 米 → 大号 326 件 / 小号 490 件 / 抱枕套 980 件"），辅助跨 SKU/产品的分配决策。
- **完工入库**：最后一道工序完成后，**按 SKU 分别**入库。
- **加工成本核算**：该单总成本 = 全部发料成本（各材料加权成本 × 实发量之和）+ 各工序加工费之和；入库单位成本 = 总成本 ÷ 入库数量 **+ 该 SKU 的单位耗材成本**，按 SKU 分别并入移动加权平均（加工费按各 SKU 入库数量占比分摊）；
  多产品工单中，**主材成本按各 SKU 实际用量（单位用量 × 入库数量）占比分摊**（v1.15 起）。
- 状态流转：**待开始 → 加工中（第 N 道工序）→ 已完成**（可作废）。
- 列表可查看所有在制工单及当前工序进度。
- **工序超期提醒**（v1.13 起，见情景 18）：产品工序模板的每道工序可设**预期天数**；
  某工序已开始、超过预期天数仍未标记完成 → 主页提醒（显示工单号、工序、已超天数）。
- **付款记录**（v1.13 起，见情景 17）：加工费应付金额（各工序加工费合计）+
  付款记录数组（日期、金额）；付款状态：未付款 / 部分付款 / 已付清。
- **实物直发说明**：原材料可由供应商直发加工商（实物不经自家仓库），账面上仍按"采购入库 → 发料出库"两笔记账，库存数量保持一致。

### 4.7 库存管理（核心）
- 成品、原材料实时库存，**按 SKU 跟踪**（数量 + 加权平均成本 + 库存金额）。
- **虚拟组合产品**不持有实物库存：库存列表中展示其**派生可售数量**
  （= min( ⌊各组件库存 ÷ 单位用量⌋ )），并醒目标注"虚拟"以示区分。
- **库存流水**：每一次变动一条记录——时间、**SKU**、类型（采购入库/发料出库/完工入库/销售出库/盘点调整/其他）、关联单据、变动数量、变动后结存、操作人。
- 流水可按产品/SKU/类型/时间范围筛选，可导出 Excel。

#### 4.7.1 盘点（v1.8 起，见情景 8）
- **盘点单**（STK）：用户任选 SKU 子集（按产品/分类/手工勾选），系统带出**账面数量**，
  用户录入**实盘数量**，自动计算**差异 = 实盘 − 账面**（盘盈/盘亏）。
- 确认后：库存直接调整为实盘数量，生成"盘点调整"流水；
  盘盈按当前加权成本计价入账，盘亏按当前加权成本核减库存金额。
- 每个 SKU 记录**最后盘点时间**（取该 SKU 最近一次已确认盘点单的时间）；
- 盘点单列表/库存列表可按"最后盘点时间"筛选排序（如"超过 30 天未盘点"），
  支持用户**分批盘点**；
- 状态流转：**草稿 → 已确认**（可作废，作废回滚调整）。

### 4.8 出库管理（手动）
- 出库单：单头（单号、**出库类型**、出库日期、关联平台单号/备注、操作人）+ 明细数组。
- **出库类型**（v1.13 起，见情景 15）：
  - **销售出库**（默认）：明细选择**平台映射**（见下方规则）；
  - **报废出库**：用于次品/损坏/过期等损耗，明细**直接选择内部 SKU**（不走映射，
    报废不是销售行为），必填**报废原因**；数量扣减库存，成本按当前加权成本计入**损耗**，
    报表可查看损耗汇总。
- **销售出库必须按"平台映射"操作，不能直接选择基础产品 SKU**（v1.10 起，见情景 9）：
  - 明细行选择一条平台映射（可按平台商品 ID / SKU 编号 / 产品名搜索）；
  - **选中映射后自动显示对应图片**（映射的平台商品图片，未上传则用内部 SKU 图片），
    辅助拣货核对（v1.11 起，见情景 10）；
  - 系统解析映射 → 内部产品 SKU（由 SPU + SKU 确定）→ 扣减其库存；
  - 出库单的**去向渠道默认取映射的平台**（如"非平台产品"或 Amazon），可修改；
  - 单据与流水中同时留存映射快照（平台、账号、ID1、ID2）与内部 SKU，便于对账。
- 确认后按 SKU 扣减库存（不允许扣成负数，给出提示）。
- **虚拟组合 SKU 出库**（v1.6 起）：
  - 校验各组件实物库存充足（不足则提示缺哪个组件、缺多少）；
  - 按组成明细展开，**扣减各组件 SKU 的库存**（虚拟产品本身无库存可扣，
    其派生可售数量随组件扣减自动减少）；
  - 库存流水按组件逐条记录，关联同一出库单并标注来源虚拟 SKU；
  - 出库成本 = Σ（组件加权成本 × 数量），用于成本统计。
- 支持作废（回滚库存；虚拟组合单作废时回滚各组件库存）。

### 4.9 报表 / 看板
- **首页看板**：库存预警列表、在制工单数、本月入库/出库汇总。
- **库存预警**分两类，均在主页报警：
  1. **固定安全库存预警**（4.2/4.3）：库存低于 SKU 安全库存阈值；
  2. **动态可用天数预警**（v1.12 起，见情景 11）：
     - 日均出库速度 = 历史窗口内出库总量 ÷ 窗口天数（按 SKU 的出库流水统计）；
     - **剩余可用天数 = 当前库存 ÷ 日均出库速度**；
     - 可用天数 **< 门槛值** → 主页报警（显示当前库存、日均速度、可用天数、门槛）；
     - 虚拟组合产品按**派生可售数量**参与计算；
     - 日均出库为 0（窗口内无动销）不报警，显示"无动销"；
     - 参数：**历史窗口**（默认 30 天）与**门槛**（默认 10 天），
       全局默认值在基础设置中维护，**可按 SPU 或 SKU 单独覆盖**
       （优先级：SKU > SPU > 全局）。
  3. **在制工单超期提醒**（v1.13 起，见情景 18）：工序超过预期天数未完成的加工单。
- **补货建议**（v1.13 起，见情景 14）：
  - 按 SKU 计算：**建议补货量 = 目标库存天数 × 日均出库速度 − 当前库存 − 在制数量
    （加工中工单）− 在途数量（未入库采购单）**，小于 0 按 0 计；
  - 目标库存天数为参数（默认 30 天，全局/SKU 可设，沿用三级覆盖）；
  - 日均出库速度沿用动态预警的同窗口口径；
  - 一键生成**采购单草稿**（直接采购类产品）或**加工单草稿**（委外加工类产品），
    数量预填建议值，可修改后提交。
- **供应商对账**（v1.13 起，见情景 17）：
  - 按供应商 + 时间段汇总采购单与加工单：单据金额、已付金额、未付金额、
    **欠款天数**（= 当前日期 − 单据日期，按未付清单据逐单计算）、付款状态；
  - 支持录入付款（逐单或合并）、导出 Excel 发给供应商对账。
- 库存总览表（数量、成本、金额）。
- 按**渠道**统计出库量（按时间段）。
- 成本查询：每个产品当前加权成本及近期入库成本记录。
- **SKU 平均库存周期（周转天数）**（v1.7 起，见情景 7）：
  - 随时可查每个 SKU：选定期间内的期初/期末库存、**平均库存**（由库存流水的逐日结存积分得出）、出库总量、**平均库存周期 = 平均库存 × 期间天数 ÷ 期间出库量**；
  - 默认统计近 30 天，可自定义时间范围；可导出 Excel；
  - 口径说明：因不分批次追踪，该值为期间加权估算（非逐件精确天数）；期间出库量为 0 时显示"—"并标注积压。

### 4.10 基础设置
- 渠道维护（增删改，如 Amazon-US、TikTok、线下客户；系统预置"非平台产品"不可删除）。
- 用户管理（管理员）。
- **库存预警全局默认**：历史窗口天数（默认 30）、可用天数门槛（默认 10）、
  补货目标库存天数（默认 30）。
- 数据导出（Excel）。

### 4.13 数据导入（期初，v1.13 起，见情景 12）

- 提供 **Excel 模板下载**与批量导入：产品（SPU+SKU）、原材料（SPU+SKU）、
  供应商、渠道、平台映射。
- **期初库存导入**：按 SKU 录入期初数量与**单位成本**，确认后生成"期初入库"流水，
  作为移动加权平均的初始值；已存在库存的 SKU 提示覆盖/累加选择。
- 导入前校验（编号格式、必填项、引用存在性），逐行报告错误，全部通过才写入。

### 4.14 退货入库（v1.13 起，见情景 16）

- **退货入库单**（RTN）：单头（单号、退货来源渠道、原出库单号[可空]、日期、备注）
  + 明细（产品 SKU、数量、**成色**）。
- **成色**决定去向：
  - **良品**：增加库存，入库成本按当前加权成本计价，生成"退货入库"流水；
  - **不良品**：不入正品库存，自动生成一张**报废出库单**（原因=退货不良品）记损耗。
- 状态流转：**待确认 → 已入库**（可作废，回滚）。

### 4.11 编号规则（统一）

格式：**3 位字母前缀 + 6 位顺序号**，子号码在主号码后加 `-<3位数字>`。

| 对象 | 前缀 | 示例 |
|------|------|------|
| 产品 | PRD | PRD000001 |
| 原材料 | MAT | MAT000001 |
| 供应商 | SUP | SUP000001 |
| 成品采购单 | POP | POP000001 |
| 原材料采购单 | POM | POM000001 |
| 加工单 | WKO | WKO000001 |
| 出库单 | OUT | OUT000001 |
| 盘点单 | STK | STK000001 |
| 退货入库单 | RTN | RTN000001 |
| 产品/原材料 SKU（子号） | 主号-序号 | PRD000001-001、MAT000001-002 |
| 采购单明细（子号） | 主号-序号 | POP000001-001 |
| 加工单工序（子号） | 主号-序号 | WKO000001-002 |

- 序号全局连续、自动生成，不允许手工修改，作废单据不占新号也不回收号。
- 渠道、库存流水、用户不编号（流水按时间排序）。

### 4.12 平台产品对应（映射，v1.9 起，见情景 9）

- 映射精确定位内部产品：**由 SPU 编号 + SKU 子编号确定**（如 PRD000001 + PRD000001-001）。
- 每个**产品 SKU** 可建立多条**平台映射**，字段：
  - **平台**（取自渠道列表，如 Amazon、TikTok）
  - **账号**（平台店铺账号，自由文本）
  - **平台商品 ID 1**（不限格式，如 ASIN / itemId / 平台 SKU）
  - **平台商品 ID 2**（不限格式，用途由用户自定，可空）
  - **平台商品图片**（可选上传；未上传时使用内部 SKU 图片）
  - 备注
- **默认映射**（v1.10 起）：每个 SKU 创建时自动生成一条默认映射——
  平台=`非平台产品`、账号=`默认账号`、ID1=SKU 编号、ID2=空（ID 可修改）；
  系统预置渠道"非平台产品"（不可删除）。线下/直接发货的出库就走默认映射。
- **唯一性约束**：以上四个值（平台 + 账号 + ID1 + ID2）**各自都允许重复，
  组合起来必须唯一**；重复组合保存时给出明确提示。
- 支持按产品、平台、账号筛选；可导出 Excel。
- 用途：**出库的唯一入口**（4.8，出库按映射操作）；
  第二期平台订单对接时，凭映射把平台商品自动匹配到内部 SKU（自动出库的前提）。

## 9. 典型业务情景（验收用例）

> 来自用户的真实业务描述，作为开发完成后反复校验的验收标准。
> 每个情景标注了需求覆盖情况和系统内的预期操作路径。

### 情景 1：豆袋椅套的委外加工（布料 → 印花 → 裁片 → 缝制）

**业务描述**：根据待补库存数量计算所需布料 → 从布料商购进布料 → 布料送印花厂印花
（有时布料商和印花厂是同一供应商）→ 印好送裁片厂裁片 → 裁好送缝制厂缝制 →
缝制完成送仓库入库。

**覆盖情况**：✅ 覆盖（v1.3 起）。

**系统操作路径**：
1. 产品"豆袋椅套"配置：主材=布料（单位用量 X 米/件）、工序模板=[印花, 裁片, 缝制]；
2. 创建原材料采购单（布料商）→ 入库（实物可直发印花厂，账面仍记"入库→发料"两笔，见 4.6 实物直发说明）；
3. 创建加工单（WKO）：指定主材=布料及输入量（各 SKU 计划总用料不得超过输入量）；
4. 工序"印花"开始：记录印花厂、开始时间，系统按建单的主材输入自动发料（布料出库）；
   布料商=印花厂时，供应商选同一家的"加工商"身份即可（供应商类型可多选）；
5. "印花"完成 → "裁片"开始（记录裁片厂、开始时间、数量、加工费）→ 依此类推到"缝制"；
6. "缝制"完成 → 完工入库，系统按 发料成本+各工序加工费 核算单位成本并入加权平均。

### 情景 2：拉链作为辅料先备货、缝制时再发出

**业务描述**：拉链不是最终产品，但从拉链厂购进后作为库存保管；当缝制厂需要时，再出库送过去。

**覆盖情况**：⚠️ v1.2 未覆盖（只支持单一主材 + 开工一次性发料）→ ✅ **v1.3 已修订**：
产品物料清单支持"主材 + 辅料"，辅料指定投入工序；加工单支持按工序发料。

**系统操作路径**：
1. 原材料建档"拉链"（类型：原材料；设安全库存可享库存预警）；
2. 产品"豆袋椅套"物料清单增加辅料：拉链（单位用量 1 条/件，投入工序=缝制）；
3. 平时：原材料采购单（拉链厂）→ 入库，拉链作为原材料库存保管；
4. 加工单执行到"缝制"工序开始时：发料（拉链出库，数量自动=计划数量×1，可调整）→ 送缝制厂。

### 情景 3：女式单肩包成品直采、快进快出

**业务描述**：直接从手袋厂购入成品，通常到货当天或一两天内发货出去。

**覆盖情况**：✅ 覆盖。周转快慢对系统无影响。

**系统操作路径**：
1. 产品"女式单肩包"来源方式=直接采购；
2. 到货：成品采购单（POP，手袋厂）→ 确认入库；
3. 发货：出库单（OUT，选去向渠道）→ 库存扣减；
4. 按渠道统计报表中可看到该产品的出库去向分布。

### 情景 4：出库耗材不计库存、只计成本

**业务描述**：有些产品出库时需要包装袋、标签贴纸等耗材。耗材比较琐碎，不记录在系统中
（不建库存、无出入库），但其成本要计入产品成本。

**覆盖情况**：⚠️ v1.3 未覆盖 → ✅ **v1.4 已修订**：
产品档案新增"单位耗材成本"字段（估算值，默认 0），成品入库核算成本时自动计入
（采购入库 4.5.1、完工入库 4.6 均适用），随移动加权平均滚动。
**v1.16 修订**：该字段由产品（SPU）级改为 **SKU 级**，同一产品不同 SKU 可设不同耗材成本。

**系统操作路径**：
1. 产品"女式单肩包"的 SKU 设置：单位耗材成本 = 0.8 元（包装袋 0.5 + 标签 0.3 的估算）；
2. 采购入库 100 件、单价 20 元 → 入库单位成本 = 20 + 0.8 = 20.8 元，并入加权平均；
3. 日常出库只扣产品数量，耗材不产生任何单据；
4. 耗材估算价变化时，修改该 SKU 的单位耗材成本字段即可，只影响之后的入库核算，
   已有库存成本不回溯调整。

### 情景 5：一个产品多个 SKU（变体）

**业务描述**：大部分产品有多个 SKU——同款女包分颜色、同款豆袋椅套分大号/小号。
椅套生产中，裁片时就要分别提交大号/小号的数量要求，裁片送缝制厂也要分别记录大号/小号数量。
拉链作为一种物料，按长短分不同 SKU。同一产品的不同 SKU 通常来自同一个供应商；
同一产品不同批次可能来自不同供应商、不同价格。

**覆盖情况**：⚠️ v1.4 未覆盖（只有单一 SKU）→ ✅ **v1.5 已修订**：
产品与原材料均改为 SPU + SKU 两级结构；库存、成本、采购、加工、出库全部落到 SKU 级；
加工单计划与各工序投入/产出均按 SKU 分列。

**系统操作路径**：
1. 产品"豆袋椅套"（PRD000001）下建 2 个 SKU：`PRD000001-001`（尺寸=大）、`PRD000001-002`（尺寸=小）；
   物料清单主材=布料，单位用量按 SKU 分别设置（大 1.5 m、小 1.0 m）；
   辅料=拉链（指定材料 SKU，如 MAT000003-001 = 20 cm）、投入工序=缝制；
2. 原材料"拉链"（MAT000003）下按长短建 SKU：`MAT000003-001`（20 cm）等；
3. 创建加工单：计划明细填 大号 100 / 小号 50；
4. 裁片工序开始：数量明细分别记录 大号 100、小号 50；完成送缝制；
5. 缝制工序开始：发料拉链 150 条（100+50，自动算出），数量明细同样分大号/小号记录；
6. 完工按 SKU 分别入库，成本按各 SKU 入库数量分摊加工费后并入各自的加权平均；
7. 采购时：同一产品的各 SKU 默认用产品的默认供应商，换供应商/改价格直接体现在
   当次采购单上（单头供应商 + 明细单价），不同批次互不影响。

### 情景 6：虚拟组合产品（捆绑装）

**业务描述**：例如"带内衬袋的豆袋椅套"——它自己不作为单独产品入库，引用某一种
豆袋椅套和内衬袋。出库这种产品时，它本身的可售库存和被引用的产品库存都要减少。
需要**任意产品、任意数量**组合的功能。

**覆盖情况**：⚠️ v1.5 未覆盖 → ✅ **v1.6 已修订**：
产品新增"虚拟组合"类型，SKU 级组成明细（组件 SKU + 数量）；
虚拟产品不建实物库存，可售数量由组件库存派生；出库按组成展开扣减组件库存。

**系统操作路径**：
1. 实物产品"豆袋椅套"（PRD000001-001 大号等）与"内衬袋"（PRD000005-001）正常建档、入库；
2. 新建产品"带内衬袋的豆袋椅套"（类型=虚拟组合），SKU 组成明细 =
   `PRD000001-001` × 1 + `PRD000005-001` × 1；
3. 库存列表中该产品显示派生可售数量：如椅套 80、内衬袋 120 → 可售 80（标注"虚拟"）；
4. 出库单选择该虚拟 SKU、数量 10 → 系统校验组件充足后：
   椅套 `PRD000001-001` −10、内衬袋 `PRD000005-001` −10，
   两条组件级流水关联同一出库单；虚拟产品可售数量自动变为 70；
5. 该虚拟产品**不能**出现在采购单、加工单中（无入库入口），系统做限制。

### 情景 7：随时查看每个 SKU 的平均库存周期

**业务描述**：用户希望随时查看每种 SKU 从入库到出库的平均天数（库存周转速度）。

**覆盖情况**：⚠️ v1.6 未覆盖 → ✅ **v1.7 已修订**：
4.9 新增"SKU 平均库存周期（周转天数）"报表，基于库存流水按期间加权估算。

**系统操作路径**：
1. 打开"库存周期"报表，默认展示近 30 天每个 SKU 的：
   期初/期末库存、平均库存、出库量、**平均库存周期（天）**；
2. 可切换时间范围（如近 7 天 / 近 90 天 / 自定义），可按产品筛选、导出 Excel；
3. 示例：某 SKU 近 30 天平均库存 60 件、出库 40 件 → 平均库存周期 = 60 × 30 ÷ 40 = **45 天**；
4. 出库量为 0 的 SKU 显示"—"并标注积压，辅助清仓决策。

### 情景 8：盘点（支持分批盘点）

**业务描述**：盘点时用户可以直接修改库存数据，系统自动计算增加/减少的数量；
记录每种 SKU 的最后盘点时间，让用户可以分批盘点。

**覆盖情况**：⚠️ v1.7 未覆盖 → ✅ **v1.8 已修订**：
4.7.1 新增盘点单（STK）与 SKU 级"最后盘点时间"。

**系统操作路径**：
1. 打开库存列表，按"最后盘点时间"升序筛选出最久未盘的一批 SKU（如 20 种布料）；
2. 新建盘点单，勾选这批 SKU，系统带出账面数量；
3. 逐行录入实盘数量，系统实时显示差异（+3 / −2 …）；
4. 确认盘点单：库存调整为实盘数，生成"盘点调整"流水
   （盘盈按当前加权成本入账，盘亏按加权成本核减），这些 SKU 的最后盘点时间刷新为今天；
5. 下次盘点时再筛"超过 30 天未盘点"的 SKU，实现滚动分批盘点；
6. 盘点单可作废，作废回滚库存调整并回退最后盘点时间。

### 情景 9：平台产品对应（映射）

**业务描述**：每个产品可以对应多个平台、不同账号、不同平台商品（需要两个不限格式的
ID 值）。所有值都可以重复，但组合起来必须唯一。

**覆盖情况**：⚠️ v1.8 未覆盖 → ✅ **v1.9 已修订**：
4.12 新增平台产品映射模块，组合唯一约束。

**系统操作路径**：
1. 打开产品"女式单肩包"SKU `PRD000002-001`（红色）的映射管理；
2. 新增映射：平台=Amazon、账号=店铺A、ID1=B0XXXXXXX1、ID2=AMZ-SKU-RED-01；
3. 同一 SKU 再增映射：平台=TikTok、账号=店铺B、ID1=1729xxxxxx8901、ID2=（空）——
   各字段单独重复都没问题；
4. 若误录一条四元组完全相同的映射，保存时提示"该组合已存在"，阻止重复；
5. 第二期对接平台订单后，系统凭（平台、账号、ID1、ID2）反查内部 SKU，实现自动出库。

**v1.10 补充规则**：
- **所有出库都按平台映射操作，不能直接选择基础产品**（4.8）；
- 每个 SKU 创建时自动生成默认映射：`非平台产品 / 默认账号 / ID1=SKU 编号 / ID2=空`，
  线下发货（不经过任何平台）的出库使用默认映射；
- 出库单的去向渠道默认取映射平台，单据留存映射快照 + 内部 SKU，便于对账；
- 示例：线下批发发 10 个红色女包 → 出库单选映射"非平台产品/默认账号/PRD000002-001"，
  数量 10 → 系统扣减 SKU `PRD000002-001` 库存 10。

### 情景 10：产品图片与出库自动带图

### 情景 11：按出库速度的动态库存预警

**业务描述**：根据一段时间的历史出库速度（件/天）计算剩余库存可用天数；
小于门槛值就在主页报警。默认 30 天历史、10 天门槛；可按 SPU 或 SKU 单独设置。

**覆盖情况**：⚠️ v1.11 仅有固定安全库存预警 → ✅ **v1.12 已修订**：
4.9 新增动态可用天数预警，参数支持全局/SPU/SKU 三级覆盖。

**系统操作路径**：
1. 基础设置确认全局默认：窗口 30 天、门槛 10 天；
2. 爆款"小号豆袋椅套"单独设置：SKU 级 窗口 14 天、门槛 7 天
   （动销快，用更短窗口和更低门槛）；
3. 系统每日（或实时）计算：该 SKU 近 14 天出库 140 件 → 日均 10 件/天，
   当前库存 65 件 → 可用 6.5 天 < 门槛 7 天 → **主页报警**；
4. 用户据此创建加工单补货；某 SKU 窗口内无出库则显示"无动销"，不报警。

### 情景 12：期初数据导入

**业务描述**：系统上线时，现有产品、原材料和库存需要批量导入，不能逐个手工录入。

**覆盖情况**：⚠️ v1.12 未覆盖 → ✅ **v1.13 已修订**：4.13 新增 Excel 批量导入与期初库存导入。

3. 再导入期初库存表（SKU、数量、单位成本）→ 生成"期初入库"流水，
   加权平均成本以导入成本为初始值，系统正式启用。

### 情景 13：到货差异与分次入库

**业务描述**：供应商可能分批发货，或实际到货少于采购数量。

**覆盖情况**：⚠️ v1.12 采购单仅"待入库→已入库"整单入库 → ✅ **v1.13 已修订**：
4.5 支持分次入库与差异结案。

**系统操作路径**：
1. 采购单 POP000001：椅套大号 500 件；
2. 第一次到货 300 件 → 录入本次入库 300 → 状态变"部分入库"，库存 +300；
3. 第二次到货 150 件 → 再入库 → 累计 450/500；
4. 供应商确认剩余 50 件不发了 → 将 50 件结案为差异（填原因"供应商少发"）→ 单据完成；
5. 库存只按实际到货 450 件记账，单据上完整保留订量/实收/差异痕迹。

### 情景 14：补货建议量

**业务描述**：根据出库速度自动算出每种 SKU 该补多少货，最好能一键生成单据。

**覆盖情况**：⚠️ v1.12 只有预警没有建议量 → ✅ **v1.13 已修订**：4.9 新增补货建议。

**系统操作路径**：
1. 打开"补货建议"页：列出各 SKU 的当前库存、在制数量、在途数量、日均速度、
   **建议补货量** = 目标天数(30) × 日均速度 − 库存 − 在制 − 在途；
2. 示例：某 SKU 日均 5 件、库存 40、在制 50、在途 0 → 建议 = 150−40−50 = **60 件**；
3. 委外加工类产品点"生成加工单"→ 草稿已预填产品与数量，确认即发料开工；
   直接采购类产品则生成采购单草稿。

### 情景 15：不良品 / 报废出库

2. 明细直接选 SKU `PRD000001-001`、数量 5、原因"缝制次品"；
3. 确认 → 库存 −5，按当前加权成本计入损耗；月度损耗报表中可见。

### 情景 16：退货入库

   "WKO000012 印花工序已超期 2 天"；
3. 用户电话跟进加工商后在工单上更新进度，提醒消除。

### 情景 19：同一原材料跨产品/SKU 共享与分配

**业务描述**：有些原材料可以用于多个 SKU 产品的制作。例如同一花色的布料，既能制作
豆袋椅套大号/小号两个 SKU，还能制作不同形状的产品（如抱枕套）；有时同一批布料需要在
不同 SKU 之间分配，且分配比例在加工过程中才最终确定（印花完成后、裁片时才决定各裁多少）。
这时需要跟踪原材料在每个加工阶段完成后，能够制作的不同产品的数量。

**覆盖情况**：⚠️ v1.14 部分覆盖（同一 SPU 内多 SKU 共享主材已支持，见情景 5；跨产品共享
与按阶段可产数量跟踪未覆盖）→ ✅ **v1.15 已修订**：加工单支持多产品（同主材、同工序模板）
合并下达，计划明细跨产品按 SKU 分列、定向工序前可调整分配比例；新增"在制可产数量"跟踪（4.6）。

**系统操作路径**：
1. 产品"豆袋椅套"（大号/小号 SKU）与"抱枕套"的 BOM 主材均指向同一材料 SKU（蓝花布
   `MAT000010-001`），工序模板一致（印花 → 裁片 → 缝制），单位用量按 SKU 分别设置；
2. 采购蓝花布 500 米入库（实物可直发印花厂，账面仍记两笔）；
3. 创建加工单，产品组选择 [豆袋椅套, 抱枕套]，指定主材=蓝花布、输入量 500 米，
   计划明细暂填 大号 100 / 小号 100 / 抱枕套 150（合计用料须 ≤ 主材输入量）；
4. "印花"工序开始，系统按主材输入自动发料 500 米；印花完成时按材料总量记录产出
   490 米（损耗 10 米），此时布料尚未定向到具体 SKU；
5. 工单显示**在制可产数量**：余布 490 米 → 大号 326 件 / 小号 490 件 / 抱枕套 980 件
   （按各 SKU 单位用量独立折算，辅助决定怎么裁）；
6. 与客户确认后将计划调整为 大号 120 / 小号 80 / 抱枕套 200，"裁片"工序按 SKU 记录
   实裁数——布料自此定向到具体 SKU；
7. "缝制"完成，按 SKU 分别完工入库；主材成本按各 SKU 实际用量占比分摊，
   加工费按入库数量占比分摊，并入各自的加权平均。
