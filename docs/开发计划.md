# PocoERP 开发计划（v1.0，待确认）

> 基于 [需求文档.md](需求文档.md) v1.14 与 [用例图.md](用例图.md) 制定。
> 状态：**待用户确认** —— 确认后从第 0 期开始。

---

## 总体策略

- 按用例图 **P1 → P2 → P3** 分四期推进，**每期结束都是可运行、可验收的版本**，
  并用需求文档第 9 章对应情景逐条验证。
- 每完成一期：本地跑通 → 提交推送（`push-git.sh`）→ 用户确认后再进入下一期。
- 仓库结构（monorepo）：

```
pocoerp/
├── server/          # Express + Mongoose 后端（API 端口 3000）
│   ├── models/      # Mongoose 模型（对应需求文档第 5 章 12 个集合）
│   ├── routes/      # REST API
│   ├── services/    # 核心服务：编号生成、库存事务、成本核算、预警计算
│   └── .env.example
├── web/             # Vue 3 + Vite + Element Plus 前端（开发端口 5173，代理到 3000）
├── uploads/         # 图片存储（gitignore）
└── docs/            # 需求文档、用例图、部署文档（现有 md 移入）
```

## 第 0 期：骨架与技术验证（风险前置）

1. 初始化 server/web 骨架、`.env.example`、ESLint/基础配置
2. **验证 MongoDB 实例**：连接测试 + **副本集/事务支持检测**
   （事务是库存一致性的底线；若实例未开副本集，先出修复方案给用户确认再动）
3. 基础设施服务：
   - **编号生成服务**（PRD/MAT/SUP/POP/POM/WKO/OUT/STK/RTN + 子号规则，需求文档 4.11）
   - **库存事务服务**（库存变更 + 流水写入在同一事务；移动加权平均成本核算）
   - JWT 登录 + 三角色权限中间件 + bcrypt；初始管理员种子账号

**交付**：空系统可登录，数据库连通，编号/库存两个核心服务有单元测试。

---

## 第 1 期：P1 核心业务闭环

4. 基础档案：供应商、渠道（预置"非平台产品"）、原材料（SPU+SKU）
5. 产品模块：SPU+SKU 建档、BOM（主材/辅料/按 SKU 用量）、工序模板、图片上传、单位耗材成本
6. 平台映射：CRUD + 组合唯一约束 + **SKU 创建时自动生成默认映射**
7. 采购管理：成品/原材料采购单、入库（先整单入库，分次入库放第 2 期）
8. 委外加工：加工单、按工序发料、工序记录（按 SKU 分列数量）、完工入库、
   成本核算（材料 + 加工费 + 耗材）
9. 库存与流水：SKU 级库存、流水查询、虚拟组合派生可售量
10. 销售出库：按映射开单、自动带图、虚拟组合展开扣减、作废回滚
11. 期初数据导入（Excel 模板 + 校验 + 期初入库流水）

**验收**：情景 1、2、3、4、5、6、9、10、12 逐条走通。

---

## 第 2 期：P2 日常运营增强

12. 采购分次入库与差异结案（情景 13）
13. 盘点单（STK）+ 最后盘点时间 + 分批盘点筛选（情景 8）
14. 出库类型扩展：报废出库；退货入库单 RTN（良品回库/不良品转报废）（情景 15、16）
15. 预警体系：安全库存预警 + 动态可用天数预警（三级参数）（情景 11）
16. 补货建议 + 一键生成采购/加工单草稿（情景 14）
17. 工序超期提醒（预期天数 + 主页提醒）（情景 18）
18. 首页看板整合（预警、超期、在制、本月汇总）

**验收**：情景 7~18 中剩余条目逐条走通。

---

## 第 3 期：P3 管理与分析

19. 付款登记（采购单/加工单）、供应商对账报表（欠款天数）（情景 17）
20. SKU 平均库存周期报表（情景 7）、渠道出库统计、成本查询
21. 各列表 Excel 导出补齐

## 第 4 期：部署与验收

22. 服务器部署：Node 环境、PM2 进程管理、Nginx 反向代理、前端构建产物托管、
    `.env` 注入（凭据只走环境变量）
23. 每日数据库备份脚本（保留 7 天）
24. `docs/部署文档.md`：部署步骤、常用运维命令、备份恢复方法
25. **总验收**：18 个情景 + 用例图全部走一遍，出验收清单

## 协作方式约定

- 每完成一个模块会本地自测（API 测试脚本 + 页面走查说明），
  用户随时可 `npm run dev` 起本地环境试用；
- 每一期推送后汇报：完成内容、验收操作步骤、发现的问题；
- 需求变更随时提：小改动直接做，影响数据结构的先更新需求文档再动手。
